The legacy `.sch` currently contains engineering notes and does **not** contain a complete electrically connected component/netlist implementation.

The cache library contains local engineering symbol definitions for the principal ICs. These symbols are migration aids and are not manufacturer-certified KiCad libraries.

## 2. KiCad migration rule

Modern KiCad uses `.kicad_sch` for schematic files containing symbol and connection information. Legacy `.sch` files can be opened and converted when saved; legacy projects require the cache library for correct symbol recovery.

The migration must therefore preserve the legacy source and create a modern schematic only after the symbols, pin mappings, connections and power domains are explicitly verified.

## 5. Power / decoupling migration

The native schematic must explicitly represent, rather than only document, the following:

- 24 V input protection boundary
- 24 V bulk capacitor
- local IC bypass capacitors
- six isolated converter input/output domains
- 3V3_MEAS and 3V3_CTRL separation
- ADC AVDD/DVDD
- ADC AGND/DGND strategy
- dedicated REFIN
- TMCS1123 supply decoupling
- STM32 supply decoupling
- ISO1044 supply decoupling
- CP/PP protection
- safety control supply separation

Prototype passive values may remain engineering baselines until manufacturer-specific requirements and measured stability are verified.

## 6. Symbol verification gate

Before ERC:

- verify package identity
- verify every physical pin number
- verify pin electrical type
- verify hidden/power pins
- verify pin names
- verify footprint association
- verify NC pins
- verify exposed/thermal pads where applicable
- verify reference/value fields

Known deliberate HOLD:
- AMC1311BDWVR physical pin mapping must not be guessed.
- STM32G474RET6 physical pin assignment must be verified against the selected package/datasheet.
- STM32G031K8T6 physical pin assignment must be verified against the selected package/datasheet.
- REF1 exact MPN remains open.

## 7. Native schematic connectivity gate

A file may only be marked **CONNECTED** after all of the following are true:

1. Components exist as real schematic symbols.
2. Pins are physically mapped.
3. Wires or labels create the intended nets.
4. Power symbols and PWR_FLAG strategy are explicit.
5. No accidental cross-domain connection exists.
6. No isolated return is shared incorrectly.
7. CP/PP paths are represented.
8. Safety paths are represented.
9. CAN isolation boundary is represented.
10. Zone A/B measurement channels are represented independently.
11. All six voltage and six current channels are present.
12. The schematic opens without rescue/import loss.

## 8. ERC gate

ERC is **NOT PASSED** at M2.9-K preflight.

Required validation command/tool:
- KiCad schematic ERC
- or `kicad-cli sch erc` using the installed KiCad version

Required outputs:
- ERC report
- error count
- warning count
- intentional exclusions, if any
- unresolved pins list
- power-input/power-output conflicts
- no-connect review

No ERC-clean claim may be made from static text inspection.

## 9. DRC gate

PCB DRC remains separate from schematic migration.

Required later:
- verified footprints
- complete netlist
- PCB connectivity
- clearance rules
- isolation rules
- thermal rules
- manufacturing constraints

M2.9-K does not authorize fabrication.

## 10. Phase-diagnostic preservation

The schematic must preserve the Zone A/B diagnostic architecture.

For each phase:
- pre-EVSE / Zone A measurement
- post-EVSE / Zone B measurement
- synchronized timestamps
- voltage/current phase relationship
- `DeltaPhi = Phi_B - Phi_A`

The diagnostic software must not attribute a phase anomaly to the EVSE merely because Zone B differs from Zone A; measurement uncertainty, wiring effects and operating state must be considered.

Capacitor recommendations remain engineering candidates only. No automatic repair command is authorized.

## 12. Current technical conclusion

The repository now has a coherent point-to-point wiring contract, but the existing legacy `.sch` is still a notes-based engineering baseline rather than a connected schematic.

The correct next implementation step is therefore to create/convert the native `.kicad_sch` using KiCad itself or a validated KiCad-compatible generation path, then run ERC against that actual file. Manually fabricating a `.kicad_sch` text file without KiCad validation is explicitly rejected for this project.
