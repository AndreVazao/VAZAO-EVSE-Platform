## Interpretation alongside the native netlist

The KiCad 10.0.6 export currently contains 24 components and 165 nets, but only three nets contain multiple pin nodes; 151 exported nets are unconnected-pin nets. The geometry defects above are consistent with the connectivity concerns, but do not by themselves explain every ERC finding.

The exported netlist also shows suspicious cross-connections involving U19 and U2. See the [connectivity audit](M2.9-K-NETLIST-CONNECTIVITY-AUDIT.md) for the exact nodes. Do not “repair” these by guessing from the component names or the source notes.

## Required evidence-first correction sequence

1. Preserve this legacy file and its cache library unchanged as the reference source.
2. Build an authoritative pin worksheet for every instantiated part: exact orderable part number/package, official pin number/name, symbol pin number/name/type, footprint pad number, and datasheet citation.
3. Validate custom symbol definitions against the exact manufacturer datasheet and package. In particular, do not use the current ADS131M06, TMCS1123 or MCU abstractions as production-accurate physical pinouts without completing that review.
4. Reconstruct intended connectivity from explicit design intent, approved interface requirements and manufacturer documentation. Mark unresolved signals as **TBD** rather than inventing nets.
5. Correct symbols and geometry on a dedicated working branch, then export a fresh netlist and compare it against an approved connectivity table.
6. Run ERC and PCB DRC, review all remaining violations, and obtain qualified electrical/safety review before fabrication or any mains energization.

## Safety boundary

This audit is not an electrical design approval. It does not authorize PCB fabrication, connection to an EV, or mains energization. High-voltage isolation, creepage/clearance, protective earth, overcurrent protection, emergency stop and contactor feedback require qualified review.
