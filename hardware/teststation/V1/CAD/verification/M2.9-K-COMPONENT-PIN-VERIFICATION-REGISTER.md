# M2.9-K component and symbol pin-verification register

Date: 2026-10-16  
Status: open engineering register; **not** a certified symbol library or approved BOM.

## Why this register exists

The native KiCad export is mechanically valid but has only three multi-pin nets across 24 components and the ERC reports extensive unconnected pins. The legacy custom cache contains eight symbol definitions. Some are known to be incomplete or have incorrect electrical pin types. Before interpreting connectivity, every custom symbol must be reconciled to the exact orderable component, package, manufacturer pin table and footprint.

## Confirmed additional mismatch: AMC1311

The current cached `AMC1311BDWVR` symbol defines pins 1–8 as VINP, VINN, GND1, VDD1, VOUTP, VOUTN, GND2 and VDD2. TI's official AMC1311 datasheet (Rev. C) instead lists the DWV 8-pin package as:

| Pin | Official pin name | Function |
|---:|---|---|
| 1 | VDD1 | High-side power |
| 2 | IN | Analog input |
| 3 | SHTDN | Shutdown input |
| 4 | GND1 | High-side ground |
| 5 | GND2 | Low-side ground |
| 6 | OUTN | Inverting analog output |
| 7 | OUTP | Noninverting analog output |
| 8 | VDD2 | Low-side power |

Official evidence: [TI AMC1311 datasheet](https://www.ti.com/lit/ds/symlink/amc1311.pdf), [TI AMC1311DWVR product page](https://www.ti.com/product/AMC1311/part-details/AMC1311DWVR).

This is not just a symbol naming issue: assigning the wrong functions to physical pin numbers can make subsequent connectivity reconstruction dangerously misleading. The current symbol must not be used to generate or validate a PCB footprint. TI's current official package addendum lists `AMC1311BDWVR` as an active orderable B-grade part in the 8-pin SOIC DWV package. The part string is therefore valid; the symbol pin-map mismatch remains unresolved.

## Evidence rules

For each part, the reviewer must record:

1. Manufacturer and exact orderable part number, including all package and grade suffixes.
2. Official datasheet URL and revision/date.
3. Package drawing and pin table: physical pin number, official pin name, function and any NC/thermal-pad requirements.
4. KiCad library symbol pin number/name/electrical type, and the corresponding footprint pad number.
5. Approved functional signal for each pin, its intended net, voltage domain and isolation boundary.
6. Evidence of footprint-to-symbol pin mapping and package dimensions.
7. Reviewer, review date and unresolved questions.

A family-level datasheet or a plausible pin name is not enough. Do not infer missing pins, net names, component values, or MCU peripheral assignments.

## Priority order

1. **U1/U2 ADS131M06 and U15–U20 TMCS1123** — directly affect measurement-chain validity and already have documented symbol defects.
2. **U3–U8 AMC1311** — verify isolation-amplifier package pins and domains before any channel connectivity reconstruction.
3. **U9–U14 MEE1S2405SC** — establish the exact isolated supply parts and domain boundaries.
4. **U21/U22 MCU symbols** — distinguish functional block diagrams from real package-accurate PCB symbols; then map interfaces from approved requirements.
5. **U23 ISO1044 and REF1** — confirm communication isolation and select/define the reference circuit.

## Gate before schematic repair

No connectivity should be changed solely to reduce ERC errors. First approve this register and a separate pin-to-net intent table. Corrections must be made on a dedicated working branch, preserve the legacy source, and be followed by regenerated netlist, ERC, and (when a PCB exists) DRC. A green tool exit code alone is not design approval.

This register is documentation for engineering triage only. It does not authorize PCB fabrication, connection to an EV, or mains energization; isolation, creepage/clearance, protective earth, overcurrent protection, emergency-stop and contactor feedback require qualified electrical/safety review.

## Critical package-pin cross-check — ADS131M06 and TMCS1123 (2026-10-16)

### U1/U2 — ADS131M06IPBSR, PBS 32-pin TQFP

TI's [exact orderable-part page](https://www.ti.com/product/ADS131M06/part-details/ADS131M06IPBSR) identifies `IPBSR` as the 32-pin TQFP (PBS) variant. The official [datasheet pin configuration/table](https://www.ti.com/lit/ds/symlink/ads131m06.pdf) maps physical package pins as follows:

| Physical pin | Official signal | Physical pin | Official signal |
|---:|---|---:|---|
| 1 | AIN2P | 17 | CS |
| 2 | AIN2N | 18 | DRDY |
| 3 | AIN3N | 19 | SCLK |
| 4 | AIN3P | 20 | DOUT |
| 5 | AIN4P | 21 | DIN |
| 6 | AIN4N | 22 | XTAL2 |
| 7 | AIN5N | 23 | XTAL1/CLKIN |
| 8 | AIN5P | 24 | CAP |
| 9 | NC | 25 | DGND |
| 10 | NC | 26 | DVDD |
| 11 | NC | 27 | NC |
| 12 | NC | 28 | AGND |
| 13 | AGND | 29 | AIN0P |
| 14 | REFIN | 30 | AIN0N |
| 15 | AVDD | 31 | AIN1N |
| 16 | SYNC/RESET | 32 | AIN1P |

**Direct mismatch:** the current schematic symbol/netlist labels pins 1–6 as AIN0P, AIN0N, AIN1P, AIN1N, AIN2P, AIN2N. This is not the physical PBS pin numbering in TI's datasheet. Pin 1/2 are AIN2P/AIN2N, pins 3/4 are AIN3N/AIN3P, pins 5/6 are AIN4P/AIN4N. The symbol is not just incomplete; its assigned pin numbers/functions do not match the physical package. Reconstructing sensor nets from this symbol before correction would be unsafe and could map the wrong ADC channels.

This register records the datasheet mapping only. It does not decide the intended sensor channel or polarity. ADS131M06 inputs are differential; approved channel-to-sensor mapping must separately specify positive and negative input pins.

### U15–U20 — TMCS1123 DVG 10-pin SOIC

TI's [official datasheet](https://www.ti.com/lit/ds/symlink/tmcs1123.pdf) lists this 10-pin mapping:

| Pin | Official signal | Electrical role / note |
|---:|---|---|
| 1 | IN+ | Analog current input |
| 2 | IN− | Analog current input — **not an output** |
| 3 | GND | Ground |
| 4 | ALERT | Open-drain active-low diagnostic output; connect to GND if unused per datasheet |
| 5 | VREF | Analog output; leave floating if unused per datasheet |
| 6 | VOUT | Analog output |
| 7 | OC | Open-drain active-low overcurrent output; connect to GND if unused per datasheet |
| 8 | VS | Supply |
| 9 | VOC | Analog overcurrent-threshold input; connect to VS if unused per datasheet |
| 10 | NC | Reserved; may be grounded or left floating per datasheet |

The current custom symbol omits pins 9 and 10 and assigns pin 2 the wrong electrical type. The prior ERC output-output conflict between TMCS1123 IN− and ADS131M06 DOUT must therefore not be interpreted as a valid circuit connection or solved by simply changing the ERC pin type: first rebuild both symbols with correct physical pin numbering, then re-export and inspect connectivity.

### Exact TMCS1123 variant caution

The source string is `TMCS1123A3AQDVGR`. TI's public family and orderable pages found during this review expose multiple sensitivity/order-code variants, but the exact `A3` string was not independently confirmed in the returned results. Treat the exact sensitivity variant as **unverified**, not as invalid. Confirm with TI or the purchasing BOM before component selection; do not substitute A1/A2/A4/A5 without design approval.

## Consequence for the next step

Do not reconstruct pin-to-net connectivity from the current custom symbols. First replace the ADS131M06 and TMCS1123 symbol definitions with package-accurate versions (all physical pins, correct pin names and electrical types), confirm footprint pad numbering, then regenerate the netlist and ERC. Only after that should the exported nets be compared with an approved sensor-to-ADC intent table. The legacy schematic and cached library remain preserved; no electrical wires were changed in this documentation step.
