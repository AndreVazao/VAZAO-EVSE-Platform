## U19 coordinate-frame correction

The coordinate CSV uses TI drawing coordinates with Y positive toward the top of the drawing. KiCad footprint-local Y positive points down the screen. The correct transform is:

- `X_KiCad = X_TI`
- `Y_KiCad = -Y_TI`

The candidate footprint and `validate_kicad_footprint_load.py` implement this transform. The native validator also checks:

- pin 1 above pin 2;
- pin 3 below pin 10;
- current-input row left of signal row;
- 9.75 mm row-centre separation;
- 8.89 mm signal-row vertical span.

## Pin-anchor coordinate reconstruction — review schematics

A read-only S-expression inspection of the two committed review schematics confirms the mechanism behind the netlist changes. Both files retain the same symbol-instance origins and all wire/label coordinates; only the embedded symbol definitions (and therefore pin-anchor positions) differ.

Symbol origins:
- U2: `(177.80, 60.96)` mm, rotation 0°.
- U19: `(203.20, 58.42)` mm, rotation 0°.

For the legacy baseline symbol definitions, the following pin anchors coincide exactly:

| Legacy physical pin | Pin function | Absolute anchor (mm) |
|---|---|---:|
| U2.17 | CS | (190.50, 63.50) |
| U19.3 | GND | (190.50, 63.50) |
| U2.20 | DOUT | (190.50, 55.88) |
| U19.2 | IN− | (190.50, 55.88) |
| U2.19 | SCLK | (190.50, 60.96) |
| U19.8 | VS | (190.50, 60.96) |

These coincidences explain the three multi-node nets in the baseline export. They do **not** establish valid design intent: the manufacturer pin functions show three incompatible pairings (GND/CS, analog IN−/digital DOUT, and supply VS/clock SCLK). The current master audit explicitly flags all three as suspicious. The legacy netlist is therefore a connectivity baseline for comparison, not an electrically approved golden reference.

In the migrated physical-symbol definitions, the corresponding anchors move:

| Migrated physical pin | Pin function | Absolute anchor (mm) |
|---|---|---:|
| U2.17 | CS | (190.50, 41.91) |
| U2.20 | DOUT | (190.50, 49.53) |
| U2.19 | SCLK | (190.50, 46.99) |
| U19.3 | GND | (190.50, 58.42) |
| U19.2 | IN− | (190.50, 55.88) |
| U19.8 | VS | (215.90, 58.42) |
| U19.9 | VOC | (215.90, 60.96) |

The unchanged right-side wires and labels remain at:
- `(213.36, 58.42)` → `(215.90, 58.42)`, label `B_L2_I`;
- `(213.36, 60.96)` → `(215.90, 60.96)`, label `B_L2_I_RET`.

Consequently, the migrated physical symbol attaches U19.8 (VS) to `B_L2_I` and U19.9 (VOC) to `B_L2_I_RET`. This is geometric/netlist evidence only. It is not a recommendation that either net belongs on those pins. In particular, the change from legacy U19.5 (VREF) to migrated U19.9 (VOC) on `B_L2_I_RET` is a change of physical pin function, not a harmless label rename.

### Engineering conclusion

The migration did not move the wires to the correct new pin anchors; it preserved the original geometry while replacing the pin layouts. But simply restoring the old anchor coincidences would reinstate three manufacturer-functionally suspicious connections. The correct repair is **not** to force the migrated symbols back onto the legacy connections.

The next safe step is to establish an approved pin-to-net intent table from:
1. exact TI pin functions and operating requirements for U2 and U19;
2. the legacy drawing's functional channel notes (Zone B current channels 3–5 are grouped to U2, but exact differential input pair/polarity is not approved);
3. the MCU/SPI interface allocation and the intended reference/threshold/diagnostic handling;
4. the approved analog design, including VREF/VOC/ALERT/OC use and isolated-domain returns.

Until that table is reviewed and approved, leave all wires, labels and junctions untouched. This analysis changes documentation only; no schematic, master, legacy baseline, PCB or net destination was edited.
